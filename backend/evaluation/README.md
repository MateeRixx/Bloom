# Independent evaluation workflow

This directory is for **independently annotated** images. Ground truth is never
derived from the baseline or improved predictions.

## Layout

```text
backend/evaluation/
  images/                       # source images (JPEG/PNG)
  ground_truth/                 # manual masks, 512x512, values 0 or 255
    img_001_acne.png
    img_001_redness.png
    img_001_blemish.png
  predictions/                  # generated by run_evaluation.py
  results/                      # generated CSV/JSON
  manifest.csv
  annotate_template.py
  run_evaluation.py
```

## Mask semantics

- One binary mask per concern per image: `acne`, `redness`, `blemish`.
- Foreground = 1 or 255; background = 0.
- Resolution is the pipeline's evaluation resolution, `512x512` (`RESIZE_TARGET`).
- Masks must be exactly the same shape as the pipeline prediction. The runner
  fails rather than silently resizing an annotation.
- Annotate visible lesions only; do not include hair, eyes, lips, nostrils,
  shadows, or specular highlights unless the annotation protocol explicitly
  says so. Record ambiguous cases in `manifest.csv`.
- Keep classes separate. A pixel may appear in more than one class only if the
  protocol explicitly allows overlap.

## Manifest

`manifest.csv` has these columns:

| column | meaning |
|---|---|
| `image_id` | Stable ID used in mask filenames |
| `image_file` | Filename inside `images/` |
| `source` | Where the image came from (or `self-captured`) |
| `license` | License/permission note; use `private` for non-redistributable |
| `width`, `height` | Original image dimensions |
| `annotation_status` | `pending`, `annotated`, or `excluded` |
| `concerns` | Comma-separated labels, e.g. `acne,redness,blemish` |
| `notes` | Ambiguities, skin tone/lighting notes, exclusion reason |

Do not commit private user photos. Use images with explicit permission or a
properly licensed public dataset, and record the license in the manifest.

## Creating the first labelled set

1. Add images to `images/`.
2. Add one manifest row per image with `annotation_status=pending`.
3. Generate blank 512x512 templates:

   ```bash
   cd backend
   python -m evaluation.annotate_template --image-id img_001
   ```

4. Paint masks in any image editor (white = lesion, black = background), save
   them over the generated files in `ground_truth/`.
5. Set `annotation_status=annotated` once all three masks are reviewed.
6. Run:

   ```bash
   cd backend
   python -m evaluation.run_evaluation --dataset evaluation --out evaluation/results/run_001
   ```

If no annotated images exist, the runner writes a **pending** status file and
does not produce performance numbers.

## Split and tuning policy

- Use separate calibration/validation and held-out test subsets.
- Never tune thresholds on images that are then reported as independent test
  data. If the dataset is too small to split, disclose it in the report.
- A 20–30 image set is an initial feasibility set, not proof of generalization.
- Include varied skin tones, lighting, face sizes, and difficult cases when
  ethically and practically available.

## Aggregation

Per-image metrics are written to `metrics_per_image.csv`. The JSON summary
contains macro mean/median across images/classes, valid/excluded counts (for
undefined cases), and support pixel counts. Empty-mask conventions are defined
in `backend/src/evaluation.py`.
